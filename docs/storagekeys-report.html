Section 6

Developer Task List

Tasks are ordered by priority. Each task includes a description, technical approach, and estimated effort.

🔴 Critical Priority

DEV-001 Reduce LCP — Optimise & Preload Hero Image Critical
LCP is 10.8 s on mobile and 11.1 s on desktop. The hero image is almost certainly the LCP element. It needs to be served as a next-gen format (WebP/AVIF), properly sized for each breakpoint, and preloaded. The <link rel="preload"> tag must be the first resource hint in <head>.
Blade template public/images Effort: 1–2 days

Steps:
  • Convert hero image to WebP (use cwebp or Squoosh)
  • Add srcset with sizes for mobile (480px), tablet (768px), desktop (1280px)
  • Add <link rel="preload" as="image" href="hero.webp" fetchpriority="high"> in <head>
  • Set loading="eager" and fetchpriority="high" on the hero <img>
  • Remove any lazy-load attribute from the hero
DEV-002 Eliminate 696 KiB of Unused CSS Critical
Nearly 700 KiB of CSS is loaded on public pages but not used. This causes render-blocking and increases parse time. The root cause is likely that admin/backend CSS bundles are included on frontend layouts.
webpack.mix.js resources/views/layout Effort: 2–3 days

Steps:
  • Use PurgeCSS with Laravel Mix to remove unused rules from public CSS build
  • Split layout templates: separate public and admin CSS stacks
  • Defer non-critical CSS with media="print" onload pattern
  • Use Chrome Coverage tool to identify which selectors are unused
  • Target <300 KiB total CSS on public pages
DEV-003 Reduce Unused JavaScript (286 KiB mobile) Critical
286 KiB of JS is loaded but not executed on mobile. This delays TTI to 15.7 seconds. Likely causes: admin JS loaded on public pages, large vendor bundles, undeferred scripts.
webpack.mix.js resources/js Effort: 2–3 days

Steps:
  • Audit JS includes in frontend layout Blade files — remove admin JS
  • Add defer to all non-critical <script> tags
  • Use dynamic import() for page-specific modules
  • Move reCAPTCHA and GTM to interaction-triggered loading (already started — validate)
  • Bundle-split with webpack: separate vendor, app, admin, frontend chunks

🟠 High Priority

DEV-004 Add Rate Limiting to Account Deletion APIs High
Commits e3e6731 and 021b836 added account deletion endpoints for employees and customers. Without rate limiting, these endpoints are vulnerable to automated abuse. Laravel's built-in ThrottleRequests middleware should be applied.
routes/api.php Http/Kernel.php Effort: 0.5 days

Steps:
  • Apply throttle:5,1 middleware to deletion endpoints (5 attempts per minute)
  • Add authenticated-user check before allowing deletion
  • Log all deletion requests (user, reason, timestamp, IP)
  • Return a confirmation token that must be re-submitted within a TTL
DEV-005 Set Up GitHub Actions CI/CD Pipeline High
There is no visible automated testing or CI pipeline. Merges to main go without automated checks. Adding GitHub Actions will catch regressions before they reach production.
.github/workflows/ phpunit.xml exists Effort: 1–2 days

Steps:
  • Create .github/workflows/ci.yml — PHP lint, composer install, phpunit
  • Add .github/workflows/deploy.yml — trigger on push to main
  • Add branch protection rules on main (require PR + CI green)
  • Add Lighthouse CI to flag performance regressions per PR
DEV-006 Fix & Validate CLS on Desktop (0.227) High
The local desktop Lighthouse run shows CLS of 0.227 (the mobile live run shows 0.001 after recent fixes). Verify that the fix from commit e0863ec is fully effective by running a fresh desktop Lighthouse audit against production.
home page template Effort: 0.5 days

Steps:
  • Run Lighthouse desktop audit against live storagekeys.com
  • If CLS > 0.1: identify shifting elements via DevTools Layout Shift Regions
  • Set explicit width/height attributes on all images & embeds
  • Ensure font-display: swap or optional in @font-face for Figtree

🟡 Medium Priority

DEV-007 Implement Server-Side Caching (OPcache + HTTP Cache Headers) Medium
FCP of 4.7 s on desktop points to a slow server response (TTFB). Enabling PHP OPcache, adding HTTP cache headers for static assets, and using Laravel's route caching will significantly reduce TTFB.
.htaccess config/cache.php Effort: 1 day
